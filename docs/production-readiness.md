# Production Readiness Review

## Current deployment target
Local, single-user hackathon demonstration. The documented run command binds to 127.0.0.1. Docker Compose also binds its published port to localhost.

## Implemented safeguards
- Random local admin token generated by the init command.
- Generated .env file permission set to owner-only on POSIX systems.
- Switch agent API keys encrypted at rest with Fernet.
- Switch registration key used transiently and not stored.
- Constant-time admin token comparison.
- Strict local script/style Content Security Policy; no inline dashboard JavaScript or CSS.
- Security response headers.
- No CORS allowlist and no public binding in the native run command.
- Public GitHub URL validation before repository fetch.
- Read-only repository inspection.
- Unified diff format and path traversal checks.
- Human approval gate; no automatic repository mutation.
- Docker Compose hardening: read-only container root, dropped capabilities, no-new-privileges, localhost port binding, persistent data volume.

## Not yet production-certified
- No multi-user identity, workspace isolation, or per-user authorization.
- SQLite has no schema migration framework or managed backup strategy.
- No request rate limiting, audit export, metrics, tracing, or alerting.
- A disposable-clone patch and syntax-check sandbox exists, but the target repository's test suite is not executed. A hardened test-execution policy is still required.
- No private GitHub repository access or fine-grained GitHub App integration.
- No secrets rotation/recovery UI.
- No live Switch environment has been exercised in this development session.
- No public deployment has been performed or approved.

## Required before public production deployment
1. Add user identity and authorization with tenant isolation.
2. Move to PostgreSQL and introduce migrations, backups, and restore tests.
3. Add rate limits, structured audit logs, observability, and alerting.
4. Add a hardened, disposable test execution sandbox with no host secrets and strict CPU, memory, time, filesystem, and network limits.
5. Add credential rotation and revocation workflows.
6. Complete security review, dependency scanning, and integration tests against a real Switch server.
7. Review and approve the deployment configuration.

A passing CI run and a successful hackathon demo do not by themselves certify a public multi-user production service.
