# Publish the MergeMind Best Blog entry

The full article is maintained in [blog-entry.md](blog-entry.md). For the Flip the
Switch Best Blog track, publish that article on a developer-facing platform and
paste the public URL into the submission form. Do not submit the GitHub file URL
as the Blog post URL; the form asks for the externally published article.

## Recommended destination: DEV Community

Use [DEV Community](https://dev.to/new) as the first destination. It is free to
publish, supports Markdown, is aimed at software developers, and provides a
public article URL that judges can open without an account.

### Publish steps

1. Sign in to DEV Community or create an account at
   <https://dev.to/>.
2. Open <https://dev.to/new>.
3. Copy the complete contents of [blog-entry.md](blog-entry.md) into the editor.
4. Keep the title: **Building MergeMind: A Reviewable Engineering Workflow with Five AI Agents and Switch**.
5. Add the tags `ai`, `opensource`, `hackathon`, `agents`, and `softwaredevelopment`.
6. Add the public repository link near the top:
   <https://github.com/PSP-YN/MergeMind>.
7. Preview the article. Check that tables, code blocks, headings and links render.
8. Publish only after reviewing the verification section and replacing any
   status that has changed. In particular, do not say the live Switch workflow
   passed until you have personally run it and captured the real room.
9. Copy the published article URL and paste it into the hackathon's **Blog post**
   field.

### Important editorial checks

- Keep the article's distinction between automated CI evidence and a live
  Switch demonstration.
- Do not claim that the sandbox runs the target repository's test suite.
- Do not claim measured productivity gains or production readiness.
- Do not embed secrets, registration keys, admin tokens, API keys or private
  room screenshots.
- If the live demo is not ready by publication, retain the current limitation
  paragraph and update it later with verified evidence.

## Optional second destination: Hashnode

If you already use Hashnode, publish a cross-post at
<https://hashnode.com/create>. Use the same Markdown and tags. If both platforms
are used, set the DEV article as the canonical source or publish on DEV first
and link to it from Hashnode. Avoid two independent versions that drift.

## Submission checklist

- [ ] Article reviewed against the final build.
- [ ] Article published publicly on DEV or Hashnode.
- [ ] Public article URL opens in a signed-out browser.
- [ ] Blog URL pasted into the hackathon submission.
- [ ] The blog's repository link points to the public MergeMind repository.
