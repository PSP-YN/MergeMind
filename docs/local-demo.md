# Local five-agent demonstration

This is the reproducible local setup used for the Flip the Switch demonstration. It runs the actual Switch core API, Switch Gateway, MergeMind backend, and a local OpenAI-compatible model endpoint. It does not create a public service or expose local ports to the network.

## Services and ports

| Service | Local URL | Purpose |
|---|---|---|
| Switch core / agent bridge | http://127.0.0.1:8000 | Authenticated agent API and WebSocket |
| Switch Gateway | http://127.0.0.1:5173 | Workspace, API keys, rooms, agents |
| MergeMind | http://127.0.0.1:8001 | Five-agent workflow dashboard and API |
| Ollama | http://127.0.0.1:11434 | Local model endpoint |
| Switch PostgreSQL | 127.0.0.1:5432 | Persistent Switch data |

The MergeMind port is 8001 because Switch uses 8000 for its agent bridge. The demo scripts deliberately keep the two services separate.

## Prerequisites

- Fedora or another Linux distribution
- Python 3.11 or newer
- Docker Engine and Docker Compose plugin
- Node.js and npm
- `uv` (Astral Python package manager)
- `just`
- Ollama with the model configured in MergeMind's `.env`
- A local Switch source checkout. Set `SWITCH_DIR=/absolute/path/to/switch` if it is not at `~/projects/hackathon/switch`.

## First-time setup

### 1. MergeMind

    git clone https://github.com/PSP-YN/MergeMind.git
    cd MergeMind
    bash scripts/setup.sh

This creates the Python virtual environment, installs backend dependencies, and creates a private `.env` if one does not already exist. Never commit `.env`, the SQLite database, or agent credentials.

### 2. Switch

Clone the official Switch repository if it is not already available:

    git clone https://github.com/sandbox-quantum/switch.git ~/projects/hackathon/switch
    cd ~/projects/hackathon/switch
    just init-env

The Switch initialization command generates local-only secrets and prints the Gateway administrator login. Keep those values private. Do not overwrite an existing Switch `.env`.

Install Gateway dependencies once:

    cd gateway
    npm ci
    cd ..

### 3. Local model

Start Ollama and pull the model configured in MergeMind:

    ollama serve
    ollama pull qwen2.5-coder:3b

The model can be changed through the `MERGEMIND_LLM_*` variables in MergeMind's local `.env`. Do not put provider API keys in this repository.

## Start and stop the complete stack

From the MergeMind checkout:

    bash scripts/start-demo.sh

The script:
- starts Switch's persistent PostgreSQL and initialization containers;
- starts Switch core on port 8000;
- starts the Switch Gateway development UI on port 5173;
- starts MergeMind on port 8001;
- waits for the HTTP health endpoints and reports Ollama availability;
- writes logs and PID files under `~/.local/state/mergemind-demo`.

To use a different Switch checkout:

    SWITCH_DIR=/absolute/path/to/switch bash scripts/start-demo.sh

To stop the three application processes without deleting database volumes:

    bash scripts/stop-demo.sh

The Switch database is retained. Docker volumes are not removed by the stop script.

## Provision the room and five agents

1. Open http://127.0.0.1:5173 and sign in using the Gateway administrator account generated by `just init-env`.
2. Open **API Keys** and create a **Registration Key**. This is not an agent API key. A short expiry (for example, 7 days) is sufficient.
3. Open **Agents** and register one temporary external agent named `mergemind-bootstrap`. The Switch room-creation API requires an initial agent for an internal-only room.
4. Open **Rooms → New room** and create a private internal room named `MergeMind Engineering Review`. Add the temporary bootstrap agent. Add these room roles: coordinator, planner, researcher, implementer, reviewer. The role instructions should require evidence-based handoffs and prohibit direct target-repository writes.
5. Copy the room ID from the room detail page.
6. From the MergeMind checkout, run:

       bash scripts/register-switch.sh

   Enter the agent bridge URL (normally `http://127.0.0.1:8000`), the room ID, and the registration key when prompted. The registration key input is hidden and is not written to disk by the script.
7. In the Switch Gateway, open the room and add all five agents:
   - `mergemind-coordinator`
   - `mergemind-planner`
   - `mergemind-researcher`
   - `mergemind-implementer`
   - `mergemind-reviewer`
8. Remove the temporary bootstrap agent from the room after all five MergeMind agents have been added.
9. Open http://127.0.0.1:8001 and paste `MERGEMIND_ADMIN_TOKEN` from MergeMind's local `.env` into the dashboard. Confirm **5/5 agents connected** before starting the workflow.

The registration key is used only during registration. MergeMind stores the five returned agent API keys encrypted in its local SQLite database using `MERGEMIND_ENCRYPTION_KEY`. Back up the encryption key securely; losing it makes the stored agent credentials unrecoverable.

## Run the demonstration

Use a public repository you are authorized to inspect. Avoid private code or sensitive information because the task text and selected repository context are sent to the configured model provider.

Suggested task:

> Inspect the repository's input validation and error handling. Identify one concrete bug or missing edge case, propose the smallest safe unified diff, and independently review the proposal. Do not apply the patch or change any branch.

Expected sequence:

1. Coordinator accepts the task and addresses the Planner in the shared Switch room.
2. Planner produces bounded steps and acceptance criteria, then hands off to Researcher.
3. Researcher reads repository evidence and cites relevant paths/excerpts.
4. Implementer proposes a minimal unified diff. The target repository remains unchanged.
5. Reviewer independently checks the proposal, flags correctness/security/test gaps, and returns a decision.
6. MergeMind records the proposal and review and waits for a human decision.
7. The operator approves or rejects. Approval records the decision; it does not apply, commit, push, merge, or deploy the patch.

## Verification checklist

Before recording, verify all of the following:

- [ ] `curl -fsS http://127.0.0.1:8000/health` returns a healthy Switch response.
- [ ] `curl -fsS http://127.0.0.1:8001/health` returns MergeMind status `ok`.
- [ ] Switch Gateway lists the shared room and all five MergeMind agents.
- [ ] MergeMind reports five registered agents and 5/5 live connections.
- [ ] A narrow task completes all five addressed handoffs in the actual Switch room.
- [ ] Repository evidence, proposed diff, and independent review appear in MergeMind.
- [ ] The workflow reaches the human decision state.
- [ ] The target repository's Git working tree is unchanged.
- [ ] No patch was automatically applied or pushed.

Automated CI and unit tests do not replace this live integration check. If any item fails, record the exact error and do not claim the five-agent demo is complete.

## Troubleshooting

| Symptom | Action |
|---|---|
| Switch health endpoint fails | Check `~/.local/state/mergemind-demo/switch-core.log` and Docker PostgreSQL status. |
| Gateway login fails | Use the credentials generated by the Switch `just init-env` command; do not assume default credentials. |
| Registration returns 401 | Use a Registration Key, not an agent's own API key. Confirm the agent bridge URL is correct. |
| Registration returns 409 | A role name already exists. Inspect existing agents before considering a re-registration/overwrite. |
| One or more agents remain offline | Add all five to the exact selected room; check Switch core logs and MergeMind worker logs. |
| Model request fails | Check Ollama is running, the model is pulled, and the configured model name matches. |
| Port conflict | Stop the conflicting service or set `MERGEMIND_PORT`, `SWITCH_PORT`, or `GATEWAY_PORT` consistently. |
